# DECISIONS — 技術・設計判断の記録(簡易ADR)

形式: 番号 / 日付 / 状態 / 決定 / 理由 / 影響

---

## ADR-001: 新規プロジェクトは `orsedia/` サブディレクトリに配置する

- 日付: 2026-07-11 / 状態: 採用
- 決定: リポジトリ直下ではなく `orsedia/` 配下に本プロジェクトを置く
- 理由: リポジトリには既存の別ゲーム(知育ゲーム、3D RPG『アルヴェリア』)が
  ルートと `rpg/` に存在し、上書き・混在を避けるため
- 影響: ルート README.md にはゲーム一覧行を追加するのみ。本プロジェクトの
  README・docs・TASKS はすべて `orsedia/` 配下

## ADR-002: バックエンド(Node.js + SQLite)の導入を Phase 3 以降へ延期

- 日付: 2026-07-11 / 状態: 採用
- 決定: Phase 1〜2 はフロントエンドのみで完結し、セーブは localStorage を使う
- 理由: 面白さの検証にサーバーは不要。構成を半減させ反復速度を優先。
  静的ホスティングだけで配布・テストできる
- 影響: セーブデータは version 付き JSON として設計し(TDD §4.3)、
  将来サーバー保存へ移行できる形にする。移行時に本ADRを更新

## ADR-003: 2Dトップダウン(ピクセルアート)を採用

- 日付: 2026-07-11 / 状態: 採用
- 決定: 3Dではなく2D見下ろし型で開発する
- 理由: Phaser 3 の得意領域であり、素材・当たり判定・AIのコストが低く、
  「広い世界を長期拡張する」目標に対して量産効率が最も高い
- 影響: 演出のリッチさはタイルアニメ・ライティング風演出で補う

## ADR-004: React と Phaser は EventBus 経由でのみ通信する

- 日付: 2026-07-11 / 状態: 採用
- 決定: React(HUD/メニュー)と Phaser(ゲーム本体)は型付きイベントバスで疎結合にする
- 理由: 相互参照による状態同期バグを防ぎ、どちらか一方の差し替えを可能にする
- 影響: `src/game/EventBus.ts` が唯一の接点。直接 import の相互参照は lint レビューで禁止

## ADR-005: ゲームデータは TypeScript 設定ファイルで管理する

- 日付: 2026-07-11 / 状態: 採用
- 決定: マップ・敵・会話・アイテム等は `src/game/data/` の .ts ファイルに置く
- 理由: JSON より型検査・補完・コメントが効き、小規模チームでの編集ミスを防げる。
  ロジックを含めないルールで JSON 相当の純データ性を保つ
- 影響: データ量が膨大になった段階で JSON +スキーマ検証への移行を再検討

## ADR-006: Phase 1 は画像アセットを使わず動的生成テクスチャで作る

- 日付: 2026-07-11 / 状態: 採用
- 決定: プレイヤー・敵・タイル等は Phaser の Graphics から生成した矩形テクスチャで表現
- 理由: アセット制作を待たずに動作とゲームフィールを検証できる。差し替えは
  テクスチャキーの張り替えだけで済む
- 影響: BootScene にテクスチャ生成を集約。Phase 2 でフリー素材へ差し替え予定
